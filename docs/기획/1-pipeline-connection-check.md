# 기획 #1 — 에이전트 파이프라인 연결 확인 (앱 변경 없음)

- GitHub Issue: #1 (제목: 시험)
- 변경 유형: internal (앱 코드·화면 변경 없음)
- 작성: 아르크투루스 · 기획팀장

## 1. 문제 — 누구의 어떤 문제인가

- **누구:** Zero(대표). 앱 사용자는 해당하지 않는다.
- **어떤 문제:** 이슈 → 채팅 의견 → 기획 → 커밋으로 이어지는 에이전트 파이프라인이 끝까지 동작하는지 확인해야 한다.
- 본문은 '확인용입니다' 한 줄뿐이다. 앱 사용자의 문제나 바꿀 기능이 적혀 있지 않다.
- 채팅에서 기획팀장과 개발팀장 모두 이 글을 **연결 확인**으로 판단했다.
- 제목 'jday 채팅'을 앱 내 채팅 기능으로 읽는 것은 근거 없는 추측이다. 따라서 이 기획서에서는 다루지 않는다.

## 2. 목표

- 기획 단계 산출물(기획서 파일 1개, 커밋 1개, 요약 JSON)이 정상적으로 만들어지는지 확인한다.
- 근거 없는 기능 항목이 백로그·기능 정의서·앱 코드에 들어가지 않게 한다.

## 3. 이번에 할 것

- 이 기획서 파일 1개만 `docs/기획/`에 만들고 커밋한다. 커밋에는 `Refs: #1`을 붙인다.
- 기획 요약을 출력해 다음 단계(승인·설계)로 넘어가는 경로를 확인한다.

## 4. 이번에 하지 않을 것

- 앱 코드, 화면, 모델(SwiftData), CloudKit 설정 변경
- 앱 내 채팅·메시징 기능 검토. 서버가 없는 CloudKit 구조와 개인용 범위를 벗어나므로, 별도 안건이 올라올 때 다룬다.
- `docs/development-overview.md`, `docs/CHANGELOG.md` 갱신. 기능 변화가 없기 때문이다.
- 기능 정의서(볼트 `기능/`) 수정. 출력의 대상 기능 항목은 스키마상 필수라 넣은 형식상 값이다.
- 정기 테스트의 알림 채널 404(Unknown Channel) 문제나 테스트 타깃 부재 문제 해결. 별도 운영 과제로 둔다.

## 5. 사용자 흐름

앱 사용자 흐름은 없다. 파이프라인 흐름만 적는다.

- **진입:** Zero가 이슈 #1을 등록한다 → 팀 채팅 의견이 달린다 → 기획 단계가 이 문서를 커밋한다.
- **실패:** 기획서 커밋이 없거나 요약 출력이 스키마 검증에 실패하면, 파이프라인 연결에 문제가 있는 것이다. 이 경우 봇 로그로 원인을 확인한다.
- **되돌리기:** 이 커밋 하나만 되돌리면 된다(`git revert`). 앱에 영향이 없다.
- **다음 단계:** Zero가 기획을 승인하면 개발 단계는 **구현 없이 종료**하는 것을 권장한다. 화면 디자인 단계는 건너뛴다.

## 6. 완료 기준

1. 이 파일 하나만 추가되고, 커밋 메시지가 `docs(plan): …` 형식이며 `Refs: #1`을 포함한다.
2. 커밋 후 작업 폴더에 커밋되지 않은 변경이 없다.
3. 앱 소스(`Jday/`, `JdayWidgets/`)와 `project.yml`에 변경이 없다.
4. 기획 요약이 스키마 검증을 통과하고 다음 단계로 전달된다.

## 7. 예외 상황

- Zero가 실제로 **앱 내 채팅 기능**을 의도했다면 이 기획은 닫고 새 이슈를 만든다. 새 이슈에는 ①누가 겪는 문제인지 ②지금 어떤 흐름에서 불편한지 ③바라는 결과를 적는다.
- 개발 단계가 이 기획을 구현 과제로 잘못 받으면, 4절 '하지 않을 것'을 근거로 작업 없이 종료한다.
- 같은 형식의 확인용 이슈가 반복되면 기능 백로그와 섞이지 않게 별도 라벨(예: `test`)로 구분하는 것을 제안한다.
